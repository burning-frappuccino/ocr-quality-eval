## 1. OpenCV 不支持中文路径，而且静默失败

### 现象

```python
img = cv2.imread(r"C:\Users\me\Desktop\AI学习路径\images\图.jpg")
print(img)        # None —— 不报错，就给你个 None
```

路径里有中文时 `cv2.imread` 直接返回 `None`，**不抛异常、不打日志**。
你只会看到后续代码莫名其妙地失败。

### 原因

OpenCV 底层是 C++ 实现，文件读写走的是只支持 ASCII 的接口。

### 解决

先用 numpy 把文件当二进制读进来，再让 cv2 从内存解码：

```python
import cv2
import numpy as np

def imread_cn(path):
    """读图片，支持中文路径"""
    buf = np.fromfile(str(path), dtype=np.uint8)
    if buf.size == 0:
        return None
    return cv2.imdecode(buf, cv2.IMREAD_COLOR)


def imwrite_cn(path, img):
    """写图片，支持中文路径"""
    ext = Path(path).suffix or ".jpg"
    ok, buf = cv2.imencode(ext, img)
    if ok:
        buf.tofile(str(path))
    return ok
```

> 判断技巧：如果用英文路径能读出图、中文路径读不出，
> 那就是这个坑，不用怀疑图片本身有问题。

## 2. PaddlePaddle 3.3.x 的 oneDNN 崩溃

### 现象

模型能加载，一执行推理就崩：

```
NotImplementedError: (Unimplemented) ConvertPirAttribute2RuntimeAttribute
not support [pir::ArrayAttribute<pir::DoubleAttribute>]
(at ..\paddle\fluid\framework\new_executor\instruction\onednn\onednn_instruction.cc:118)
```

### 原因

PaddlePaddle 3.3.x 默认启用 oneDNN（CPU 加速库），
但它在处理某些 PIR 属性类型时有缺陷，导致 CPU 推理直接崩溃。
上游 issue：PaddlePaddle/Paddle#77340

### 排查过程

1. 看报错最后一行 → 定位到 `onednn_instruction.cc`，说明是 oneDNN 的问题
   （而不是自己的代码写错了）
2. 搜报错关键字 → 确认是上游 bug
3. 想办法关掉 oneDNN

### 三种尝试

| 方案 | 结果 |
|---|---|
| 环境变量 `FLAGS_use_mkldnn=0` | ❌ 无效，飞桨 3.x 不再读这个变量 |
| 构造参数 `enable_mkldnn=False` | ✅ **有效** |
| 构造参数 `device="cpu"` | ❌ 无效，本来就在 CPU 上跑 |

### 解决

```python
ocr = PaddleOCR(
    lang="ch",
    enable_mkldnn=False,      # ← 关键
    ...
)
```

## 3. PaddleOCR 3.x 的 API 与旧教程不兼容

网上中文教程（包括不少 2024 年的文章）用的是 2.x 写法，在 3.7 上会直接报错。

### 写法对比

```python
# ❌ 2.x 老写法（旧教程都是这个）
ocr = PaddleOCR(use_angle_cls=True, lang="ch", show_log=False)
result = ocr.ocr(img_path, cls=True)
# 结果是嵌套列表：[[[四个角坐标], (文字, 置信度)], ...]

# ✅ 3.7 正确写法
ocr = PaddleOCR(
    lang="ch",
    use_textline_orientation=False,      # 替代原来的 use_angle_cls
    use_doc_orientation_classify=False,
    use_doc_unwarping=False,
    enable_mkldnn=False,
)
result = ocr.predict(img_path)
d = dict(result[0])
d["rec_texts"]     # 文字列表
d["rec_scores"]    # 置信度列表
d["rec_polys"]     # 四角坐标列表
```

### 参数对照表

| 2.x 参数 | 3.7 对应 |
|---|---|
| `use_angle_cls` | `use_textline_orientation` |
| `show_log` | 已移除 |
| `ocr(img, cls=True)` | `predict(img)` |
| 返回嵌套 list | 返回字典式对象，`dict(res[0])` |

> **教训**：中文教程用来建立概念，具体代码永远以官方文档或实测为准。
> 遇到 `ImportError` / `TypeError` 先看版本号。

## 4. 灰度图不能直接喂给 PaddleOCR

### 现象

```
ValueError: not enough values to unpack (expected 3, got 2)
```

### 原因

PaddleOCR 只接受 **3 通道 BGR** 图片。
`cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)` 出来的是 2 维数组（单通道），
喂进去就报这个错。

### 解决

处理完转回 3 通道：

```python
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
# ... 做各种灰度域处理 ...
result = cv2.cvtColor(gray, cv2.COLOR_GRAY2BGR)   # ← 转回来
```

注意 `COLOR_GRAY2BGR`（不是 `COLOR_GRAY2RGB`）—— 虽然对 OCR 结果影响
不大，但保持和 cv2 的 BGR 约定一致更安全。

## 5. 倾斜校正的坐标顺序陷阱

### 现象

对一张完全水平的图做倾斜检测，算出 `-90°` 的假倾斜，
把好图转歪了。

### 原因

```python
ys, xs = np.where(binary > 0)
points = np.column_stack((ys, xs))      # ❌ 这是 (y, x)
```

`np.where` 返回的是 `(行, 列)`，也就是 `(y, x)`；
而 `cv2.minAreaRect` 要的是 `(x, y)` 点集。顺序反了，
最小外接矩形就被转置了，角度自然算错。

### 解决

```python
ys, xs = np.where(binary > 0)
points = np.column_stack((xs, ys))      # ✅ (x, y)

angle = cv2.minAreaRect(points)[-1]     # OpenCV 返回 [-90, 0)
if angle < -45:
    angle += 90
# 归一后超出 ±45° 的，说明本来就是正的，不要转
if abs(angle) < 0.5 or abs(angle) > 45:
    return img, 0.0
```

## 6. Excel / WPS 会锁定 CSV 导致写入失败

### 现象

```python
with open("answers.csv", "w", encoding="utf-8-sig") as f:
    ...
# PermissionError: [Errno 13] Permission denied
```

### 原因

Excel / WPS 打开 CSV 时会持有文件锁，Python 无法覆盖。
更隐蔽的是：**WPS 进程可能在后台一直持有锁，即使你没有在编辑这个文件**。

### 解决

写临时文件 + 尝试替换 + 失败时降级：

```python
tmp = target.with_name(target.stem + "_new" + target.suffix)
with open(tmp, "w", encoding="utf-8-sig", newline="") as f:
    writer.writerows(rows)
try:
    if target.exists():
        target.unlink()
    tmp.rename(target)
except PermissionError:
    print(f"⚠️ {target.name} 正被 Excel/WPS 打开，已改写到 {tmp.name}")
```

> 另外建议：写 CSV 用 `encoding="utf-8-sig"`，
> 否则 Excel 打开中文会乱码（`utf-8` 不带 BOM，Excel 认不出来）。

## 7. 评测集制作的三个陷阱

这三个不是代码 bug，而是**方法论错误**，但危害比代码 bug 大得多。

### 陷阱 1：拿模型输出当标准答案

把 OCR 结果复制进 `answers.csv` 当"标准答案"，测出来 CER 永远很低。
这是自己给自己打分。

**判断方法**：如果"标准答案长度"和"识别结果长度"完全一样，
那你多半是复制粘贴的。

### 陷阱 2：标准答案不完整

只抄了 30 行文字，但模型识别出 75 个文字块 ——
多出来的全被算成"插入错误"，CER 虚高到 200%。

**标准答案必须覆盖图上所有文字，一个字都不能漏。**

### 陷阱 3：只看置信度，不看 CER

置信度是模型自己说的"我有多确定"，**它会撒谎**。

本项目的实证数据：

| 图片 | 平均置信度 | 实际 CER |
|---|---|---|
| 火箭回收海报 | 97.1% | 1.92% |
| 库迪咖啡海报 | 74.0% | 20.16% |
| 高校欢迎横幅 | **84.5%** | **10.34%** ← 置信度虚高 |

欢迎横幅置信度 84.5% 看着还行，实际 CER 是 10.34%，
比置信度更高的滴滴截图（91.4% / 6.20%）差得多。

**结论：置信度只能用于分流人工复核，衡量准确率必须用 CER。**
