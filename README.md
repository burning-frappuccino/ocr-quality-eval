# OCR 质量评测与人工复核分流系统

> 一个能**量化回答**「识别准不准、哪里会错、多少要人工复核」的文档识别系统。

大部分 OCR 项目止步于「能跑出文字」。但在真实业务里，需要回答的是另一类问题：

- 识别准确率**到底是多少**？（不是「看起来挺准」）
- 哪些图片会失败？**失败模式**是什么？
- 有多少结果需要**送人工复核**？对应多少人力成本？
- 试过的优化**真的有效吗**？提升了几个百分点？

这个项目就是来回答这些问题的。

---

## 核心指标

### 1. 字符错误率 CER（Character Error Rate）

OCR 领域的标准指标，衡量识别结果和正确答案差多少。

```
CER = (替换字符数 + 删除字符数 + 插入字符数) / 正确答案总字符数
```

举例：

```
正确答案：北京市朝阳区建国路88号
识别结果：北京市朝阳区建国路8号        ← 少了一个 8
CER = 1 / 12 = 8.3%

正确答案：合同编号：HT-2026-0315
识别结果：合同编号：HT-2026-03I5       ← "1" 认成了 "I"
CER = 1 / 18 = 5.6%
```

基于 **Levenshtein 编辑距离**实现（动态规划）。

### 2. 人工复核率（Review Rate）

```
复核率 = 置信度低于阈值的文字块数 / 总文字块数
```

业务含义：**每 100 页有多少要人工看一眼**，直接对应人力成本。

### 3. 误检率（False Detection Rate）

```
误检率 = 被误认为文字的图标/图案数 / 总检测块数
```

OCR 不只「认错字」，还会「无中生有」—— 把 Logo、图标、按钮当成文字。
这类误检会污染下游数据，必须单独统计。

## 实测结果

### 评测集：5 张真实场景图片 / 132 个文字块

| 图片类型 | 文字块 | 平均置信度 | **CER** | 复核率 | 耗时 |
|---|---|---|---|---|---|
| 火箭回收海报（白底红字） | 5 | 97.1% | **1.92%** | 0.0% | 3.03s |
| 抖音商城截图 | 23 | 94.2% | **5.26%** | 4.3% | 8.48s |
| 滴滴打车截图（含地图） | 75 | 91.4% | **6.20%** | 9.3% | 16.79s |
| 高校欢迎横幅（手机拍摄） | 5 | 84.5% | **10.34%** | 20.0% | 2.89s |
| 库迪咖啡海报（艺术字） | 24 | 74.0% | **20.16%** | 45.8% | 6.41s |
| **汇总 / 平均** | **132** | — | **8.78%** | **15.9%** | — |

### 文字块级统计

| 类别 | 数量 | 占比 |
|---|---|---|
| 识别正确 | 90 | 68.2% |
| 识别错误（已人工核对修正） | 26 | 19.7% |
| 误检（图标/图案被当成文字） | 16 | 12.1% |

### 关键发现：置信度不能替代 CER

| 图片 | 平均置信度 | 实际 CER | 说明 |
|---|---|---|---|
| 火箭回收海报 | 97.1% | 1.92% | 一致 |
| 库迪咖啡海报 | 74.0% | 20.16% | 一致 |
| **高校欢迎横幅** | **84.5%** | **10.34%** | **置信度虚高** |

欢迎横幅置信度 84.5% 看着还行，实际 CER 10.34%，
比置信度更高的滴滴截图（91.4% / 6.20%）差得多。

> **结论：置信度只能用于分流人工复核，衡量准确率必须用 CER 评测。**
> 这就是为什么需要一份人工核对过的评测集，而不是只看模型自己报的分数。

## 失败模式分析

### 1. 艺术字 / 装饰字体（最严重）

库迪咖啡海报 20.16% 的 CER 主要来自这里：

| 识别结果 | 实际内容 | 错误类型 |
|---|---|---|
| `生椰章铁经` | 生椰拿铁 | 形近误识（章→拿、经→铁） |
| `小黄油关式` | 小黄油美式 | 形近误识（关→美） |
| `Coti Cotfe` | Cotti Coffee | 字母形近（t→f） |
| `黑` | 黑金深烘美式 | 只识别出首字，其余丢失 |

模型对**装饰性字体、倾斜排版、低对比度文字**的识别能力显著下降。

### 2. 形近字误识（中文特有）

| 识别结果 | 实际内容 | 场景 |
|---|---|---|
| `博学驾行` | 博学笃行 | 校训 |
| `运大志向` | 怀大志向 | 标语 |
| `公上滑继续看视频` | 向上滑继续看视频 | App 提示 |
| `曹品山行` | 曹操出行 | 品牌名 |
| `图片仅供参者` | 图片仅供参考 | 免责声明 |

**笔画相近的汉字是主要错误来源**，尤其是左右、上下结构的相似字。

### 3. 误检：把图标当成文字（16 处，占 12.1%）

| 误检内容 | 实际是什么 |
|---|---|
| `回` ×4 | 库迪咖啡的方形 Logo |
| `G` / `X` / `O` | 手机状态栏图标、关闭按钮 |
| `三:` / `:` / `D` | 各类 App 图标 |
| （空文本，置信度 0.000） | 检测到区域但完全无法识别 |

这类误检在业务里会污染下游数据，必须单独处理和统计。

### 4. 粘连与截断

| 识别结果 | 实际内容 | 问题 |
|---|---|---|
| `商城推荐` | 商城 推荐 | 两个 UI 项粘成一块 |
| `直播热点团购` | 直播 热点 团购 | 三项粘连 |
| `三注深圳` | 关注 深圳 | 连笔字误识 + 漏项 |
| `问号之眼（裕` | 问号之眼（裕华楼小区店） | 文字块被截断 |

### 5. 異體字 / 繁简混用

`艾米亞公寓` → 实际为 `艾米亚公寓`（此处应为简体）

## 图像预处理实验（负结果）

### 7 种方案对比

| 方案 | 图片1 | 图片2 | 平均 | 结论 |
|---|---|---|---|---|
| **A 原图** | **91.4%** | **84.5%** | **87.9%** | ✅ 最佳 |
| B 灰度化 | 87.5% | 84.9% | — | ❌ |
| C 灰度+去噪 | 85.7% | 61.0% | 73.4% | ❌ 伤害最大 |
| D +倾斜校正 | 85.7% | 61.0% | 73.4% | ❌ |
| E +限制尺寸 | 82.1% | 61.0% | 71.6% | ❌ |
| F +CLAHE 增强 | 91.2% | 83.3% | — | ➖ 无收益 |
| G +锐化 | 88.0% | 86.3% | — | ➖ 无收益 |

### 对照实验：找原因

| 实验 | 结果 | 说明 |
|---|---|---|
| 摆正的原图 | 99.5% | 基线 |
| 故意转歪 12° | 99.5% | **模型自带倾斜鲁棒性** |
| 压暗到 35% 亮度 | 98.2% | 仅掉 1.3pp |
| 压暗 + CLAHE 增强 | 98.5% | 仅补回 0.3pp |

### 结论

**PP-OCRv5 对倾斜和光照已有很强鲁棒性。外部预处理不仅无收益，反而因边缘模糊导致置信度下降 14 个百分点。**

最终方案：**不做预处理，直接识别**。

> 这是一个「负结果」，但价值很高：网上大量教程都说「OCR 前必须预处理」，
> 实测证明在 PP-OCRv5 上对正常质量图片做预处理是有害的。
> **不要盲目套用最佳实践，要建立评测集用数据验证。**

## 快速开始

```bash
# 1. 安装依赖
pip install paddlepaddle paddleocr opencv-python pillow numpy

# 2. 把待识别图片放进 images/

# 3. 批量识别（输出到 output/）
python src/01_批量识别.py

# 4. 评测质量，得到 CER / 复核率
python src/03_质量评测_CER.py

# 5. 查看人工复核队列
cat results/人工复核清单.csv
```

### 首次运行说明

第一次运行会自动下载 OCR 模型（约 20 MB）到你本机
`~/.paddlex/official_models/`，之后运行不用再下载。

如果下载慢，可以设置国内镜像：

```bash
set HF_ENDPOINT=https://hf-mirror.com      # Windows
export HF_ENDPOINT=https://hf-mirror.com   # Linux / macOS
```

## 人工核对流程

评测集的质量决定评测结论的可信度。流程：

```
1. 图片放入 images/
2. 运行 src/01_批量识别.py          → 得到识别结果
3. 运行 src/04_人工核对工具.py       → 生成待核对清单（按置信度排序）
4. 打开清单，对照原图逐条检查：
     ✅ 识别正确 → 留空
     ❌ 识别错误 → 填写正确内容
     🗑️ 图标误检 → 填 （删除）
5. 运行 src/04_人工核对工具.py convert → 生成 eval/answers.csv
6. 运行 src/03_质量评测_CER.py        → 得到真实 CER
```

**这一步是机器替代不了的，也是这份评测数据别人抄不走的原因。**

⚠️ 常见错误：直接把模型输出当标准答案 —— 那是自己给自己打分，
CER 会永远很好看。判断方法：如果标准答案和识别结果长度完全相同，
多半就是复制粘贴的。

## 已知问题与解决

开发过程中遇到的上游库问题，详细记录见
**[docs/工程踩坑记录.md](docs/工程踩坑记录.md)**：

| 问题 | 解决 |
|---|---|
| OpenCV 中文路径静默返回 None | 用 `np.fromfile` + `cv2.imdecode` |
| PaddlePaddle 3.3 oneDNN 推理崩溃 | `PaddleOCR(enable_mkldnn=False)` |
| PaddleOCR 3.x API 与旧教程不兼容 | 用 `predict()` + `dict(res[0])` |
| 灰度图喂给 OCR 报错 | 处理完 `cv2.cvtColor(gray, cv2.COLOR_GRAY2BGR)` |
| 倾斜校正算出 -90° 假倾斜 | `np.where` 返回 (y,x)，需换成 (x,y) |
| Excel/WPS 锁定 CSV 导致写入失败 | 写临时文件 + 降级处理 |

### 这个项目的定位

不是「调用库跑通 OCR」的演示，重点在**评测体系**：

- 用 CER（字符错误率）而不是「看起来挺准」来衡量效果
- 用消融实验和对照实验验证每一项优化到底有没有用
- 把「人工复核」这个真实业务环节做成可量化的流程

项目最有价值的发现是一个**负结果**：PP-OCRv5 对倾斜和光照的鲁棒性
已经足够强，网上广泛流传的「OCR 前必须预处理」在这个模型上反而会
让置信度下降 14 个百分点。这说明**建立评测集、用数据验证，
比照搬最佳实践更重要**。
